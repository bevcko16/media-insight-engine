# Benchmarking methodology

## Rule

There are no universal benchmarks in this skill and none should be invented. A benchmark is only
used if it is in `knowledge/` (or supplied by the user) with **source, date, market, platform,
objective, buying model and format**. Without these, it is not a benchmark, it is a rumour.

## Order of comparison

1. **Plan and targets** agreed for this campaign.
2. **The campaign's own history**: same entity, equal window, prior period or prior flight.
3. **Within-account comparison**: other lines in the same account, same period, same objective.
4. **Client benchmark register** (`knowledge/<client>/benchmarks.md`), matched on context.
5. **External published benchmark**, only if asked, quoted as a range with source and date, and
   with the reasons it may not apply.

## Matching context

A benchmark applies only when it matches on as many of these as possible: market, industry,
platform, objective, optimisation event, buying model (CPM, CPV, CPC, oCPM), audience type
(prospecting vs retargeting), placement, format and duration, season, year. State which match and
which do not.

## Freshness

Platform auctions change quickly. Treat benchmarks older than about twelve months as directional
and say so. Do not present an old benchmark as current. If the date is unknown, do not use it.

## Language

- "Within the range of the client's previous three flights (0.6% to 0.9%)" is good.
- "Above industry average" without a source is forbidden.
- Never turn a benchmark into a pass/fail verdict in client copy unless the client agreed that
  benchmark as a target.

## Register format

See `templates/benchmark-register.md`. One row per benchmark, never edited in place: add a new row
with a new date so history is preserved.
